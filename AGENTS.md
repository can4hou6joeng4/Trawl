## Project Overview

Legal Document Extractor — a **desktop-only** Wails v2 app (Go backend + Vue 3/TypeScript
frontend) that extracts structured fields (defendant, ID number, litigation requests,
facts) from Chinese legal documents (`.docx`/`.pdf`/images) and exports to Excel/CSV/JSON.
The Evidence Desk (取证台) UI shows source pages beside structured records with in-place
field highlights and two-way locate.

**Desktop-only scope is deliberate**: no web mode, REST API, Docker, or browser adapters —
see `docs/superpowers/specs/2026-05-14-desktop-only-scope-design.md`. Do not reintroduce
those surfaces. (The self-hosted OCR relay gateway is external credential infrastructure,
not part of the app — it is exempt.)

```bash
# Live regression against real cloud endpoint (skipped without env)
OCR_LIVE_TOKEN=xxx  OCR_LIVE_FILE=/path/scan.pdf go test -run TestLive -v ./internal/extractor/
OCR_LIVE_GATEWAY=https://gw/api/v2/ocr/jobs OCR_LIVE_FILE=... go test -run TestLive -v ./internal/extractor/

# Release builds

```

golangci-lint excludes `frontend/`, `build/`, and `main.go`; errcheck is relaxed in
`_test.go` files. CI covers the root package plus `./internal/...` and `./cmd/...` via
`go test ./...`, and runs frontend tests separately. `gateway-worker/` has its own npm
toolchain (not wired into CI).

## Architecture

### Wails binding chain

`main.go` embeds `frontend/dist`, binds the `internal/app.App` struct, and enables native
file drag-and-drop. Every public method on `App` becomes a generated TS binding in
`frontend/wailsjs/go/app/App` (regenerated by `wails dev`/`wails build` — **never
hand-edit `frontend/wailsjs/`**). Vue components must not import `wailsjs` directly; they
go through the adapter in `frontend/src/services/api.ts` (`IApiService`), which
lazy-imports the bindings.

### Backend layers

- **`internal/app`** — Wails-facing layer: file dialogs, trial/license gating on every
  extract/preview call (shared `runExtraction` skeleton), cancellation bookkeeping (one
  in-flight extraction; a new extraction pre-cancels the previous). Progress streams via
  the `extraction_progress` Wails event. `friendlyExtractError` maps sentinel errors to
  **stable code strings**: `PDF_ENCRYPTED_OR_LOCKED`, `BAIDU_TOKEN_MISSING`, `CANCELLED`,
  `UNSUPPORTED_FORMAT: ...`. The frontend half of this contract lives in
  `frontend/src/services/errors.ts` — changing codes requires updating both sides.
- **`internal/extractor`** — extraction engine. `extractor.go` coordinates strategies and
  fronts an SHA256 content-hash LRU of `ExtractOutput` (records + per-page OCR coordinate
  lines; coordinates replay on cache hit). PDF flow (`pdf_local.go`): probe first page's
  text layer under a timeout → text present ⇒ parallel local parsing; otherwise cloud OCR
  → Windows-only system-OCR-bridge fallback (`pdf_winocr.go`). Images go straight to cloud
  OCR. DOCX parses locally (`docx.go`). `context.Context` is honored at every IO boundary
  and returns the `ErrCancelled` sentinel.
- **Cloud OCR client** (`ocr_client.go`) — AI Studio **v2 async jobs API**
  (PaddleOCR-VL-1.6): multipart submit → 5s polling (server-side real per-page progress;
  4xx fails fast, 5xx/network tolerated 3×; 15-min job cap) → result JSONL downloaded from
  an **unauthenticated signed URL**. **Dual-mode**: user token (`ocr.token`) ⇒ direct with
  `bearer` auth; else relay gateway (`ocr.gateway_url`) with `X-LE-Machine-ID` /
  `X-LE-License` headers — the app ships **zero cloud credentials**. Coordinates come from
  `parsing_res_list` blocks (VL models have no line-level `overall_ocr_res`), normalized to
  [0,1] in `ocr_layout.go`; any schema anomaly degrades that page's coordinates only,
  never the markdown/record flow (宁缺毋错). No client-side chunking (v1 legacy, retired).
- **`internal/gateway` + `cmd/ocr-gateway`** — Go relay gateway (one of two equivalent
  implementations; the **deployed production gateway is the Cloudflare Worker** in
  `gateway-worker/`, live at `ocr-gw.bobochang.cn`). Verifies machine-ID/license (same
  HMAC as `license.go`), meters trial/licensed daily quotas (20/200 submits per machine),
  per-minute rate limit, job-ownership checks, forwards with the real token
  (env/secret `OCR_GW_TOKEN`). Deploy docs: `docs/ocr-gateway-deploy.md`.
- **Field definitions** live in `patterns.go` (`PatternRegistry`:
  `defendant`/`idNumber`/`request`/`factsReason` with Chinese labels + regexes). Plain-text
  regex parsing in `parsing.go` (`parseCases` defaults to all registered fields when the
  field list is empty — the WinOCR path relies on this); OCR markdown → records in
  `markdown_parser.go`. Export format (CSV/XLSX/JSON) chosen by output extension
  (`export.go`); headers are the union of keys across records, ordered by
  `exportColumnOrder`.
- **`internal/config`** — Viper config, env prefix `LEGAL_EXTRACTOR_`
  (e.g. `LEGAL_EXTRACTOR_OCR_TOKEN`), `config/conf.yaml` searched relative to the
  executable then CWD; template auto-created. OCR keys under `ocr:`
  (`token`/`gateway_url`/`job_url`/`model`); legacy `baidu.token` honored via `GetOcr()`.
  `GetOcr` reads via viper live: **env changes apply immediately; conf.yaml edits need an
  app restart**. Trial: 7-day clock from ldflags-injected `BuildTime` (dev = unlimited).
  License: HMAC-SHA256(machineID, `LicenseSecret`) first 16 hex, `XXXX-XXXX-XXXX-XXXX`;
  machine ID = first 8 hex of SHA256(hostname+salt). `config.ResetForTest()` exists solely
  for tests that need the "config uninitialized" state (the baked gateway default makes
  cloud available by default).

### Frontend highlight pipeline

`pdfDoc.ts` renders PDF pages via pdf.js (serialized renders, generation guards) and
exposes `getTextLayout` (char-precise, CSS px). `pdfHighlights.ts` is a pure matcher:
NFKC folding (Kangxi radicals/full-width forms), context prefixes, long-field
anchor+suffix, per-field backward claiming across same-page records, line clustering,
visual-width-weighted amortization. `DocPane.vue` source priority: **pdf text layer →
OCR blocks (scans) → OCR blocks over `<img>` (photos)**; falls back to REC badges when no
coordinates. `ocrPages` flows from `ExtractResult` (backend) through `App.vue` per
current page. Guards: clear-on-page-flip, canvas-width basis sharing, rendering-in-flight
skip, silent destroy-path rejections.

## Contracts & invariants (enforced by tests — keep green)

- `testdata/extraction-fixtures/`: shared markdown→records fixture asserted by
  `TestParseMarkdownSharedFixture`. Intentional parsing changes ⇒ update
  `basic-complaint.records.json`.
- `release_policy_test.go`: release workflow embeds **no cloud credentials** (gateway
  secrets `OCR_GW_TOKEN`/`OCR_GW_LICENSE_SECRET` never appear); config template ships
  empty `ocr.token`; workflow **must** inject `config.LicenseSecret` (activation was
  silently broken before v4.2.0 when this was missing); desktop installer matrix
  (darwin/universal dmg + windows/amd64 nsis) published; Windows installer bundles the
  OCR bridge.
- **License three-way consistency**: `config.GenerateLicense` (app verify) ≡ gateway
  `verifyLicense` (tier) ≡ `cmd/license-gen` (issuance — it calls the config function
  directly). Never fork the algorithm.
- Frontend/backend error-code contract (see `internal/app` ↔
  `frontend/src/services/errors.ts`).
- `ExtractResult.ocrPages` shape (`{page, lines:[{text,x,y,w,h}]}`, normalized [0,1]) is
  consumed by `DocPane`; wailsjs models are regenerated, not edited.

## External infrastructure (owner-operated)

- Production gateway: **Cloudflare Worker** `legal-extractor-ocr-gw`, custom domain
  `ocr-gw.bobochang.cn`, Durable Object metering. Secrets via `wrangler secret put`
  (`OCR_GW_TOKEN`, `OCR_GW_LICENSE_SECRET`). Upstream:
  `https://paddleocr.aistudio-app.com/api/v2/ocr/jobs`.
- GitHub Actions secret `LICENSE_SECRET` = gateway `OCR_GW_LICENSE_SECRET` = owner's
  `~/.secrets/license-secret`. Token rotation: one `wrangler secret put`, zero app release.
- PRD for the gateway/v2 decision:
  `docs/superpowers/specs/2026-07-14-ocr-v2-jobs-and-builtin-token-prd.md`.

## Known pitfalls

- Don't hand-edit `frontend/wailsjs/` (generated) — but do commit regenerations.
- Don't reintroduce client-side PDF chunking, the sync layout-parsing API, or heartbeat
  fake progress — all retired by the v2 migration.
- Don't put any token/secret literal in source, docs, or workflows (policy tests + CI
  GitGuardian will catch it).
- `designs/` at repo root is an untracked scratch area for E2E artifacts — leave it out
  of commits.
- Empty-string env vars do not override viper defaults (viper ignores empty env values) —
  "disable the gateway" is not expressible via env; tests use `config.ResetForTest()`.
- vitest 4's V8 coverage counts branches more strictly than vitest 3; coverage thresholds
  in `frontend/vitest.config.ts` are per-glob "actual −5~10pp" guards — raise them when
  adding tests, don't lower them for convenience.
